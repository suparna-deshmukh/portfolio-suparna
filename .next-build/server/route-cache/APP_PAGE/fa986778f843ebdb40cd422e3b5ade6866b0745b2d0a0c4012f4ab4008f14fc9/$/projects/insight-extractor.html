Why

PM work dies in the gap between “I need user signal” and eight open tabs of Hacker News, Reddit and app-store reviews. A manual sweep takes days, and most of it is dedup work.

The mechanism

A four-step wizard captures the brief: topic, objective, audience, competitors, timeframe. Gemini plans the research from that brief — per-platform keywords, app hints, timeframes — then parallel fetchers hit the live APIs (Hacker News, Reddit, App Store, Play Store, GitHub, Google Trends, Product Hunt, YouTube). SQL stages clean and deduplicate the corpus, an LLM pass labels each record into insight buckets with sentiment, and the output is a fixed-format User Insights Report — snapshot, buckets, evidence, trend, competitor comparison, methodology — as shareable markdown.

Budget and guardrails

Strictly ≤3 Gemini calls per run (plan → label → synthesize). The key pool rotates on quota failure with per-key daily caps, a per-user run window limits agent runs (default 5 per rolling 5 hours), and all shared state — budget, identity, windows — lives in one store: local JSON for single-instance, Redis for multi-instance Vercel, so the free-tier quota is enforced platform-wide, never per instance.

Modes

Rapid Scan (~1 minute, one Gemini call) for a fast pass; Standard; Deep Dive (~3–6 minutes, hundreds of records, full corpus labeling); and Raw Data, which skips synthesis and hands over the CSV.

Where it runs

Deployed as a serverless app; the real run captured in the screenshots (“flipkart delivery”, deep mode) pulled 187 records across six platforms, dropped the irrelevant, and returned six buckets plus a full report in about 3.5 minutes.
