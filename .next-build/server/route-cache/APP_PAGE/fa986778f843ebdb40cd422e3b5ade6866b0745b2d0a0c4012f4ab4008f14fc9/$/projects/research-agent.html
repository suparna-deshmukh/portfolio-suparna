Why I built it

As a PM I kept doing the same thing by hand: reading threads, noting complaints, finding the pattern, drafting the spec. I wanted that loop to run itself — give it a topic, get back a prioritized pile of pain points and a first draft of the work.

Pull quoteSelect any line to reply

The 28-node workflow

The agent is a 28-node n8n workflow with auto subreddit discovery. From a topic input it scrapes Reddit and Hacker News via their APIs, aggregates 500+ pain points per run, and hands them to an LLM pipeline on Ollama (Llama 3) that classifies feedback by theme, flags competitor mentions and generates PRDs and user stories.

The scaleaggregates 500+ pain points per run

From pain points to PRD

The output is a ranked theme list with quotes attached, then a PRD skeleton: problem statement, affected users, proposed solution and open questions. For a new product area, research-to-spec time dropped by 70% versus doing it by hand.

The payoffresearch-to-spec time dropped by 70%

Scheduled, not one-shot

It runs on a schedule with a form-based UI, keyword expansion and history logging, so last week's themes and this week's themes are diffable. The history log is the part I use most — trends are visible only across runs.

What I'd change

I'd add citations back into every generated claim, and I'd make the theme taxonomy a human-editable artifact instead of a prompt. The LLM is good at drafting; it's worse at knowing what it doesn't know.

The blind spotit's worse at knowing what it doesn't know
