The problem

AskCart started from a simple observation: e-commerce search fails silently. When the catalog returns nothing, the shopper doesn't file a ticket — they just leave. I wanted to see how often that happens and what the queries actually look like, so I started with the only dataset that would tell me the truth: reviews.

Mining 94,600 reviews for signal

I built an agentic extractor on the Reddit, App Store and Play Store APIs and fed it into a 6-stage SQL pipeline. Across 94.6K reviews it isolated four root causes of search failure: vague intent, missing filter context, spelling and slang drift, and catalog gaps that no query could ever fix. Each cause got its own treatment instead of one generic "no results" page.

Ask, don't guess

The product decision was to replace the dead end with a guided follow-up: a Vercel-deployed MVP over 36K Bayesian-rated SKUs that asks one narrow question at a time — budget, use case, must-have feature — and re-runs the search with the answer. On 150 real search sessions, null results fell from 27.3% to 8%.

When the model is the fallback

A lot of the remaining misses were Hinglish: "sneekrs red", "waterproof for monsoon". I built an ML semantic fallback using multilingual embeddings for similarity search, so vague or code-mixed queries still resolve. On a 100-query eval set, top-3 relevance hit 88%.

Evals before launch

On top of search I built a RAG chatbot on LLM intent parsing and embedding search. I wrote AI evals for search, RAG and UX before the first demo; the suite passes at 96.7% (n=113) and now guards every prompt and index change. User-level click and event analytics with properties show 78.7% of searches resolve within 2 follow-ups (n=150).

What shipped

Next.js front end, SQL pipeline, Python + ML fallback, Gemini API for the chat. What I'd do differently: instrument the funnel from day one, and budget the embeddings before it budgets me.
